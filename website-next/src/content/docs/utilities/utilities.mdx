Utilities are the final local adjustment layer—not a parallel component
system. Use semantic HTML first, choose a CSS Tags component or layout when it
owns behavior, and add utilities for one independent concern at a time.

## Browse by concern

- [Colors](/utilities/colors/): surfaces, foreground contrast, brand roles,
  and feedback roles
- [Borders and radius](/utilities/borders/): logical edges, widths, styles,
  colors, and connected corners
- [Spacing](/utilities/spacing/): density-aware padding, margin, and axis gaps
- [Typography](/utilities/typography/): local size and weight adjustments
- [Layout](/utilities/layout/): display, flex, grid, position, and overflow
- [Effects](/utilities/effects/): elevation and scrims
- [Interaction](/utilities/interaction/): focus, outlines, rings, hover, and
  reduced-motion-aware press feedback
- [Anchor positioning](/utilities/anchor-positioning/): named anchors,
  position areas, and viewport fallbacks

## Cascade and theming

Utilities are shipped in the `utilities` cascade layer and consume public
theme tokens. Application CSS loaded after `css-tags` can still make deliberate
final overrides without `!important`.

```css
@import url("css-tags/index.css");

:root {
  --density-factor: 0.9;
  --border-width-thick: 0.15rem;
  --focus-ring-color: var(--accent-overt);
}
```

Import the complete library through `index.css`, or import
`utilities/utilities.css` after its required core token and theme layers when
building a custom bundle.
