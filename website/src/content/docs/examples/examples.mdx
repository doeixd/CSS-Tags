## Product cards

`layout-grid` handles the responsive columns while each `card` contains its own media and content. The grid needs no breakpoint.

## Settings form

## Feedback states

Use `role="status"` for a polite update and `role="alert"` when an urgent message should be announced immediately. The `status` attribute is the visual styling hook.

<LiveExample title="Semantic alerts">
  <layout-stack gap="var(--space-sm)">
    <div class="alert" status="success" role="status">
      <span class="alert__icon" aria-hidden="true">✓</span>
      <div><div class="alert__title">Published</div><div class="alert__body">The new version is live.</div></div>
    </div>
    <div class="alert" status="warning" role="alert">
      <span class="alert__icon" aria-hidden="true">!</span>
      <div><div class="alert__title">Payment needs attention</div><div class="alert__body">Update the card before July 30.</div></div>
      <div class="alert__actions"><button type="button">Update</button></div>
    </div>
  </layout-stack>
</LiveExample>

```html
<div class="alert" status="success" role="status">
  <span class="alert__icon" aria-hidden="true">✓</span>
  <div>
    <div class="alert__title">Published</div>
    <div class="alert__body">The new version is live.</div>
  </div>
</div>
```

## No-JavaScript disclosure

Native `details` and `summary` provide keyboard behavior and state. CSS Tags adds the surface, focus, and open-state styling.

<LiveExample title="Frequently asked questions" description="Open and close these native disclosure widgets.">
  <div data-accordion>
    <details open>
      <summary>Does this need JavaScript?</summary>
      <p>No. The browser owns disclosure behavior; CSS Tags styles it.</p>
    </details>
    <details>
      <summary>Can I change the spacing?</summary>
      <p>Yes. Set <code>--disclosure-padding</code> locally or in your theme.</p>
    </details>
    <details>
      <summary>Does it support reduced motion?</summary>
      <p>Yes. Disclosure transitions are removed when reduced motion is requested.</p>
    </details>
  </div>
</LiveExample>

## Loading content

`aria-busy` is both the semantic state and the spinner trigger. Skeletons use a small utility hook and an accessible status label.

<LiveExample title="Loading states">
  <layout-stack gap="var(--space-md)">
    <button aria-busy="true" data-spinner="small" disabled>Saving</button>
    <div role="status" aria-label="Loading article">
      <layout-stack gap="var(--space-sm)">
        <div class="skeleton box"></div>
        <div class="skeleton line" style="width: 60%"></div>
        <div class="skeleton line"></div>
      </layout-stack>
    </div>
  </layout-stack>
</LiveExample>

```html
<button aria-busy="true" data-spinner="small" disabled>Saving</button>

<div role="status" aria-label="Loading article">
  <div class="skeleton box"></div>
  <div class="skeleton line" style="width: 60%"></div>
  <div class="skeleton line"></div>
</div>
```

## Customizing a component with tokens

Component-specific variables make local theming explicit. This changes one disclosure without creating another variant system.

<LiveExample title="Locally themed disclosure">
  <details open style="--disclosure-radius: 1rem; --disclosure-padding: 1.25rem; --disclosure-border-color: var(--accent);">
    <summary>Theme me where I am used</summary>
    <p>The public tokens override this instance while preserving its behavior and semantics.</p>
  </details>
</LiveExample>

```html
<details style="
  --disclosure-radius: 1rem;
  --disclosure-padding: 1.25rem;
  --disclosure-border-color: var(--accent);
">
  <summary>Theme me where I am used</summary>
  <p>The public tokens override this instance.</p>
</details>
```

## Standalone demos

The repository also includes full-page demos in `examples/`. They are useful for testing whole themes and many components together. For learning and copying a focused pattern, start with the live recipes above.

Every repository HTML demo is published as an Astro route. Open one as a full page:

- [Library-only landing page](/examples/demo-landing-library-only/) uses only `index.css` and public library APIs.
- [Art-directed landing page](/examples/demo-landing/) adds product-specific styling to those primitives.
- [Beacon product page](/examples/demo-beacon/) combines navigation, pricing, calls to action, and a long-form footer.
- [Component catalog](/examples/demo-components/) collects cards, navigation, sidebar, and smaller components.
- [Complete component playground](/examples/demo/) exercises the broad component API and its JavaScript enhancements.
- [Alternate component playground](/examples/demo2/) demonstrates another full composition and theme.
- [Automatic semantic styling](/examples/demo-auto-styling/) shows context-aware defaults.
- [Color-scheme controls](/examples/demo-color-scheme/) demonstrates light, dark, and system color schemes.
- [Content patterns](/examples/demo-content-patterns/) covers metadata, quotes, statistics, and content groupings.
- [Element patterns](/examples/demo-element-patterns/) exercises the native and declarative element APIs.
- [Fluid typography](/examples/demo-fluid-type/) demonstrates bounded, container-relative type.
- [Navigation patterns](/examples/demo-navigation-patterns/) provides breadcrumbs and responsive pagination.
- [Full palette editor](/examples/demo-palette-full/) exposes the complete palette controls.
- [Palette layout gallery](/examples/demo-palette-layouts/) applies palette controls to composed layouts.
- [Site shell](/examples/demo-site-shell/) builds a native header, content region, and footer.
- [Theme controls](/examples/demo-theme/) demonstrates token-driven theme editing.
- [Typography specimen](/examples/demo-typography/) exercises headings, prose, figures, and rich text.

The source remains in `examples/*.html`; Astro imports it at build time, bundles the library stylesheet and enhancement scripts, and rewrites links between demos for the deployed base path.
