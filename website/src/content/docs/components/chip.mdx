Chips work well for categories, selected filters, and compact metadata. The shipped `chip` element is presentational; it does not include selection or removal behavior.

## Sizes and removable appearance

<LiveExample title="Chip sizes" compact>

    <chip size="md">Medium</chip>
    <chip size="lg">Large</chip>

  </layout-cluster>
</LiveExample>

```html
<chip size="sm">Small</chip>
<chip size="md">Medium</chip>
<chip size="lg">Large</chip>
<chip removable>Active filter</chip>
```

`removable` adds only the visual × marker. It does not make the element focusable, announce a remove action, or remove itself. For a working control, use a native button and let your application own the behavior:

```html
<button type="button" class="filter-chip" aria-label="Remove CSS filter">
  CSS <span aria-hidden="true">×</span>
</button>
```

The library does not currently ship `.filter-chip`; this pattern intentionally uses a native button as the behavior layer. You can reuse the chip tokens in your own button style.

## Public API

Use the custom element, a `data-chip` host, or the `.chip` class. Prefer
`data-variant` for visual variants so the native `role` attribute remains
available for accessibility semantics.

```html
<chip data-variant="overt">Custom element</chip>
<span data-chip data-variant="overt">Data host</span>
<span class="chip" data-variant="overt">Class host</span>
```

- Sizes: `sm`, `md`, `lg`
- Surface variants: `subtle` (default), `default`, `overt`, `muted`
- Appearance hook: `removable`

Common customization variables:

- `--chip-gap`
- `--chip-bg` and `--chip-color`
- `--chip-border-color` and `--chip-border-width`
- `--chip-radius`
- `--chip-padding-inline` and `--chip-padding-block`

Use badges for statuses and counts; use chips for tags, filters, or selections.
